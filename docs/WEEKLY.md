# 주간 문항(Weekly Questions) 가이드

OX 퀴즈의 문항은 데이터베이스가 아니라, 저장소(repo) 안의 JSON 파일로 관리해요.
서버는 시작할 때 `server/data/questions/` 아래의 모든 `<YYYY-WW>.json` 파일을 읽어
메모리에 올려서 사용해요(파일을 고치면 서버를 다시 시작해야 반영돼요).

## 파일 위치와 이름

```
server/data/questions/<YYYY-WW>.json
```

`YYYY-WW`는 ISO 주차 표기예요 (예: 2026년 45번째 주 → `2026-45.json`). 한 주에 새
문항을 여러 번 추가하면 같은 파일에 합쳐져요(merge).

## 한 주 분량 구성 (레벨당 30문제 기준)

레벨(초등/중등/고등/청년)마다 한 주에 약 30문제를 두고, 카테고리 비율은 대략:

| 카테고리 | 비율 | 30문제 기준 권장 개수 |
|---|---|---|
| 성경 (`bible`) | 90% | ~27개 |
| 넌센스 (`nonsense`) | 10% | ~3개 |

실제 게임에서는 호스트가 고른 문제 수(10/20/30)에 맞춰 같은 비율로 자동으로 섞어서
출제해요. 넌센스 문항이 모자라면 성경 문항으로 채워 넣어요(그 반대도 마찬가지). 레벨의
문제 뱅크가 요청한 문제 수보다 적으면 에러 없이 뱅크에 있는 문항을 모두 사용해요(그
이상으로 늘어나거나 중복되지 않아요). 같은 교회가 최근에 낸 문제는 문항 수가 허락하는
한 피해서 새 문제를 우선 출제해요.

## 문항 필드

각 문항은 아래 필드를 가진 객체예요:

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `id` | string | 필수 | 전체 문항 뱅크에서 고유해야 하는 안정적인 식별자. 예: `elementary-bible-031` |
| `level` | string | 필수 | `elementary`(초등) \| `middle`(중등) \| `high`(고등) \| `youth`(청년) |
| `category` | string | 필수 | `bible`(성경) \| `nonsense`(넌센스) |
| `text` | string | 필수 | 문제 문장. 전체 문항 뱅크에서 고유해야 해요 |
| `answer` | string | 필수 | `"O"` 또는 `"X"` |
| `explanation` | string | 필수 | 정답 공개 시 보여줄 짧은 설명 |
| `ref` | string | `category === 'bible'`일 때 필수 | 성경 출처(예: `"누가복음 2:7"`) |
| `week` | string | 필수 | 이 문항이 추가된 주차. `YYYY-WW` 형식, 파일명과 일치해야 해요 |

예시 (성경 문항):

```json
{
  "id": "elementary-bible-031",
  "level": "elementary",
  "category": "bible",
  "text": "다윗은 양을 치던 목동이었어요.",
  "answer": "O",
  "explanation": "사무엘상 16:11. 다윗은 아버지의 양을 치던 목동이었어요.",
  "ref": "사무엘상 16:11",
  "week": "2026-46"
}
```

넌센스(말장난 OX) 문항은 "정답(?)은 ○○예요" 형태로 묻고, `explanation`에서 말장난의
근거(동음이의어 등)를 밝혀서 O/X 판정이 명확히 설명되도록 써주세요. `ref`는 성경 문항이
아니면 생략해도 돼요.

## 새 주차 문항 추가하기

1. 위 형식에 맞춰 JSON 배열 파일을 하나 작성해요(파일 이름/위치는 아무 곳이든 괜찮아요,
   스크립트가 `week` 필드를 보고 알아서 올바른 위치에 저장해요). 예시는
   [`docs/example-week.json`](./example-week.json)을 참고하세요.
2. 검증 스크립트를 실행해요:

   ```bash
   npm run add-week -- path/to/새문항.json
   ```

   먼저 실제로 쓰지 않고 검사만 해보고 싶다면 `--dry-run`을 붙여요:

   ```bash
   npm run add-week -- path/to/새문항.json --dry-run
   ```

3. 스크립트는 다음을 검사해요:
   - 각 필드의 타입/허용값 (`level`, `category`, `answer`, `week` 형식 등)
   - 파일 안/전체 문항 뱅크에서 `id`와 `text`의 중복 여부
   - `bible` 카테고리의 `ref` 누락 여부
   - (경고만) 레벨별 권장 문항 수(30문제 기준 성경 27 / 넌센스 3)에 못 미치는지
   - (경고만) 레벨별 O/X 답이 한쪽으로 너무 치우쳤는지

   오류(ERROR)가 하나라도 있으면 아무 파일도 쓰지 않고 종료 코드 1로 끝나요. 경고
   (WARNING)는 참고만 하면 되고, 실행은 계속돼요.
4. 오류가 없으면 `server/data/questions/<week>.json`에 저장돼요(이미 있으면 기존 문항
   뒤에 합쳐져요).

## 배포하기

문항 파일은 git으로 관리되는 일반 파일이라, 커밋하고 푸시하면 배포에 그대로 포함돼요.

```bash
git add server/data/questions/<week>.json
git commit -m "문항: <week> 주차 추가"
git push
```

Render 등 호스팅에서 빌드할 때 저장소의 모든 파일(데이터 JSON 포함)이 함께 배포되고,
서버가 재시작되면서 새 문항이 자동으로 로드돼요. 별도의 DB 마이그레이션이나 설정은
필요 없어요.
